## Booking and fares

| Date | Decision | Affects | SRS/SPMP updated |
|---|---|---|---|
| 2026-10-05 | **Booking requires a road route.** A fare is only calculated from the OpenRouteService road distance; if no road route is available the passenger cannot book (no straight-line fare bookings). | Booking, fare | No |
| 2026-10-05 | **Standard fare is fixed.** The passenger pays the fare shown at confirmation. It is calculated from the admin-managed fare settings (base fare + per-km rate per vehicle type). It is labelled "Fare", not "Estimated fare". | Booking, fare, admin fare settings | No |
| 2026-10-05 | **Fares keep centavos.** Fares are shown and stored to the centavo (e.g. ₱40.92); they are not rounded to whole pesos. | Fare, payments | No |
| 2026-10-05 | ~~**Barangay tariffs from Poblacion** (first version).~~ Replaced by the 2026-10-11 final fare model below. | Fare | No |
| 2026-10-11 | **Final fare model.** (1) A trip between Poblacion and any point inside barangay X (by the barangay's official boundary), in either direction, is charged barangay X's admin-set tariff for the vehicle type, per trip, if that tariff is active. (2) Every other trip inside Trinidad (barangay to barangay, within Poblacion, within one barangay, or a barangay without an active tariff) uses the per-km fare. (3) Out-of-area trips use the per-km fare. All rates and tariffs are set by the admin. | Fare, admin fare settings, admin tariffs | No |
| 2026-10-14 | **Barangay tariffs are separate documents.** Stored as `barangayTariffs/{barangayId}` {name, tricycle, motorcycle, active, updatedAt, updatedBy}; admin-only writes; readable by signed-in users (one document per barangay, because one combined document exceeded the Firestore rules expression limit). Barangays without a saved tariff use per-km. Barangay IDs/names exist in `firestore.rules`, `admin/src/tariffs/barangays.ts` and `src/constants/barangays.ts`; a unit test checks they are identical — change all together. | Fare, admin tariffs | No |
| 2026-10-28 | **Barangay boundaries source.** `data/trinidad-barangays.geojson`: the 20 barangays of Trinidad, Bohol, extracted from the Philippines Subnational Administrative Boundaries (adm4, version v03, valid from 2025-02-13), PSA/NAMRIA via OCHA HDX. Credit the source in the documentation and the app's About screen; check the license on the HDX dataset page. | Fare, documentation | No |
| 2026-10-28 | **Barangay lookup.** The boundaries are mapped to the tariff IDs by name in `src/constants/barangayBoundaries.ts` (generated by `scripts/buildBarangayBoundaries.mjs`; [latitude, longitude], 5 decimals): 19 barangays plus `poblacion` (PSGC 0701244015). PSA code 0701244011 does not exist in the source. `findBarangayAt()` returns the barangay containing a point, or the nearest one within the 150 m service-area edge tolerance. Checked by `npm run test:unit`. | Fare | No |
| 2026-10-28 | **Applying tariffs (approved, being implemented).** New standard bookings store `fareBasis` (`per_km` or `barangay_tariff`), the pickup and destination barangay IDs, and `perKmRate` for per-km bookings. Bookings without `fareBasis` (older app versions) are still accepted and treated as per-km. Rules check that a tariff fare equals the active admin tariff; they cannot check that the pin is really in that barangay (known limit; a server-side check needs Cloud Functions/Blaze). If the tariff changes between quote and confirm, the passenger is shown the new fare and must confirm again. If tariffs fail to load or take longer than about 5 seconds, the app uses the per-km fare. | Booking, fare, rules | No |

## Out-of-area trips

| Date | Decision | Affects | SRS/SPMP updated |
|---|---|---|---|
| 2026-10-05 | **Out-of-area covers pickup OR destination outside Trinidad.** A trip is out-of-area if either end is outside the Trinidad, Bohol service area. | Out-of-area trips, service area | No |
| 2026-10-05 | **One driver per request.** A request is offered to one driver at a time. ~~The driver proposes a fare;~~ the passenger confirms that driver or chooses another (fare part replaced 2026-10-11). There is no counter-offer. | Out-of-area trips | No |
| 2026-10-05 | **Out-of-area requests expire after 30 minutes.** (The admin can set 1–30 minutes; see System settings, 2026-10-14.) | Out-of-area trips | No |
| 2026-10-11 | **Out-of-area fare is the admin per-km fare and is FINAL.** Drivers do not propose an amount: a driver accepts the request at the per-km fare and the passenger confirms that driver or chooses another. Barangay tariffs never apply to out-of-area trips. Labelled "Fare" everywhere (no "agreed" or "reference" fare). | Out-of-area trips, fare | No |

## Drivers, contact and privacy

| Date | Decision | Affects | SRS/SPMP updated |
|---|---|---|---|
| 2026-10-05 | ~~**Passenger cannot contact the driver yet.**~~ Replaced by the 2026-10-13 contact entry below. | Booking status | No |
| 2026-10-13 | **Contact numbers are shared only between the passenger and the assigned driver while the trip is active.** During an accepted, arrived or in-progress trip the passenger sees the driver's number and the driver sees the passenger's name and number, each with a Call button. Nobody else (e.g. drivers browsing open requests) can read them, and sharing stops when the trip is completed or cancelled. | Booking status, driver trip, privacy | No |
| 2026-10-13 | **Driver vehicle type is chosen from a list, never typed.** `vehicleType` must be exactly `tricycle` or `motorcycle`; the admin sets it with a dropdown (a typed value such as "Motorcycle " hides all requests from that driver). | Drivers, admin | No |
| 2026-10-14 | **Revoking and restoring drivers.** Admins can revoke or restore a driver's verification on the Drivers page. Revoking requires a reason (visible to admins only) and takes the driver offline; a driver revoked mid-trip can still finish that trip. The app shows "Driver access revoked. Please contact the TriGo administrator." (never the reason) together with the support contacts. A passenger cannot confirm an out-of-area driver who was revoked after accepting; the request returns to searching. | Drivers, admin, out-of-area trips | No |
| 2026-10-24 | **Vehicle identification.** Drivers have `vehicleBrand` (1–30 characters), `vehicleModel` (1–40) and `vehicleColor` (1–20), required on new driver applications. The admin can correct them at approval and edit them on the Drivers page. Passengers see "Color Brand Model · PLATE" (e.g. "Red Honda TMX 155 · ABC 1234") once a driver is assigned and on the out-of-area "Confirm Your Driver" screen. Drivers approved before this show only vehicle type and plate until the admin fills the details in. | Drivers, booking status, admin | No |

## Commission and earnings

| Date | Decision | Affects | SRS/SPMP updated |
|---|---|---|---|
| 2026-10-13 | **Driver Home shows fares collected, not earnings.** "Fares collected" (Today / This week, since Monday 00:00) is the sum of the driver's own completed trips' `finalFare`, labelled "Before commission". ~~Commission is not shown until the commission feature exists.~~ Commission is now shown on the driver Earnings tab. | Driver Home, earnings | No |
| 2026-10-13 | **Commission policy (final).** Admin-set PERCENTAGE of the final fare on every completed trip (standard and out-of-area). The admin sets the payment period (e.g. 3 or 7 days); the period total is due at its end. The driver pays via GCash to TriGo's admin number ~~or cash at the office~~ (GCash only since 2026-10-19) and enters the reference number; the admin confirms it on the admin website. Unpaid after the due date: a warning is shown to the driver; after the admin-set grace period: suspended from accepting bookings (can still log in and see the balance) until the overdue amount is confirmed paid; the suspension lifts automatically. Permanent ban only by the admin manually. Replaces the earlier 24-hour settlement idea. | Commission, driver payments, admin, driver suspension | No |
| 2026-10-14 | **Commission amount** = final fare × percentage ÷ 100, rounded to the nearest centavo (same as fares). | Commission | No |
| 2026-10-19 | **Commission payments and earnings: TriGo does not move real money.** Drivers pay commission by GCash only (outside the app) to TriGo's GCash account and submit the amount and GCash reference number; partial payments from ₱1.00 up to the balance are allowed and pay the oldest debt first; each reference number can be used once. The admin verifies manually and confirms or rejects (with a reason). Admin cash-outs (GCash, Maya, bank transfer) happen outside the app and are only recorded in TriGo, capped at the amount collected; records cannot be edited. TriGo's GCash account (name and number) is an admin setting in System settings, shown to drivers. Trips completed before the commission feature are not charged. Automatic payments through a payment provider (e.g. PayMongo) are a future enhancement requiring a registered business and Blaze. | Commission, driver payments, admin earnings | No |

## Admin website

| Date | Decision | Affects | SRS/SPMP updated |
|---|---|---|---|
| 2026-10-13 | **Admin is a web application.** Built in `admin/` (React + Vite + Firebase Web SDK), hosted on Firebase Hosting, in the same repository and Firebase project as the mobile app. Admin access is the custom claim `admin: true`, granted only by the local `scripts/setAdminClaim.mjs` script. | Admin | No |
| 2026-10-14 | **Admin read access.** Admins can read all user profiles, bookings, driver records and out-of-area requests for management and reports. Admins cannot edit bookings or out-of-area requests. Open requests past `expiresAt` are shown as Expired on the admin website (the app never writes status `expired`). | Admin, privacy | No |
| 2026-10-14 | **Reports.** Reports use Firestore count/sum aggregates only (no booking documents downloaded). A completed or cancelled booking counts on the day of its `updatedAt`. Ranges up to 62 days are charted per day, longer ones (max 366 days) per calendar month. Charts are plain SVG (no chart library); CSV export has per-period rows and a summary. ~~Commission on the report is an estimate at the current rate.~~ Since 2026-10-23 the report shows recorded commission (the sum of commission actually recorded on trips). | Admin reports | No |
| 2026-10-14 | **System settings.** Admins edit the out-of-area settings as one object: accept out-of-area requests on/off, request expiry 1–30 whole minutes, driver search radius 1–50 whole km. The app picks them up the next time it loads fare settings; requests already sent keep their expiry. Support contacts `supportContacts/{id}` {label, phone, active, sortOrder, updatedAt, updatedBy}: admins add, edit, hide and delete them; app users read only active ones, shown on the passenger Help & Support screen and to drivers (Profile and the revoked-access card) with tap-to-call. | Admin, help & support | No |
